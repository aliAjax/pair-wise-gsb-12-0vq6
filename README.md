# 车辆调度 · 保养停机与备件核销台

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

在车辆调度小工具的基础上扩展出「保养停机 + 备件核销」闭环。数据保存在浏览器 localStorage，
刷新后任务、停机、库存与补录版本保持一致；界面提供「一致性自检」按钮，可随时重新派生存量数据核对。

## 业务规则（全部集中在 `src/rules/engine.ts`，以纯函数实现）

| 编号 | 规则 | 落点 |
| --- | --- | --- |
| R1 | 执行中车辆不能报修；紧急报修须先回收任务并写明原因 | `recallTask` / `createOrder` |
| R2 | 单车同一时刻只保留一张在修单 | `openOrderOf` 校验 |
| R3 | 备件领用不能超过库存（可用 = 结存 − 预占） | `requestParts` / `availableOf` |
| R4 | 缺件转待料，并释放本次已预占数量 | `tryReserve` 原子回滚 / `retryPending` |
| R5 | 完工须录里程、质检、旧件回收；质检不合格退回待修 | `finishOrder` |
| R6 | 合格完工后冻结备件与里程；补录只生成带原因的版本 | 完工快照 + `amendOrder` 追加版本 |

### 备件两阶段模型

1. **申请领用**：在修工单逐行预占「可用库存」；任一项不足，整单回滚已预占数量、转待料（`pendingParts`，不占库存）。
2. **核销台确认**：预占记录转为「核销」流水，数量才真正出库；也可释放预占恢复库存。
3. **待料复工**：备件入库后按 `pendingParts` 重新原子预占，全部满足即核销并复工，否则继续待料。
4. **完工/补录**：未核销预占或待料需求未处理时不能完工；补领生成核销流水、退回生成退库流水，均挂在新版本上，原始快照永不改写。

## 分层结构

```
src/
├─ types.ts            领域模型（纯数据结构）
├─ data/               数据层：种子数据、localStorage 持久化
│  ├─ schema.ts
│  ├─ seed.ts
│  └─ storage.ts
├─ rules/engine.ts     规则层：纯函数 + RuleError，零框架依赖，可独立单测
├─ stores/fleet.ts     状态层：Pinia，只做「规则计算 → 替换状态 → 持久化」
└─ components/         界面层：车辆、工单、备件、指标、toast
```

数据、规则、状态、界面互不越界：界面不直接改状态，状态层不写业务判断，规则层不知道 Vue 的存在。

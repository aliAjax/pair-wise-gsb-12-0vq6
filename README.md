# 车辆调度 · 保养停机与备件核销台

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`（含 `tsc` 类型检查）

在车辆调度小工具基础上扩展的**调度 + 保养停机 + 备件核销**一体化前端。
数据默认保存在浏览器 localStorage，每次操作整份快照事务性落盘，刷新后任务、停机、库存、补录版本保持一致。

## 业务规则

| 主题 | 规则 |
| --- | --- |
| 报修入口 | 执行中车辆不能普通报修；紧急报修必须**先回收执行中任务**并填写回收原因（≥5 字） |
| 单车单据 | 一辆车同一时间只保留一张未完工维修单（待修 / 在修 / 待料 / 质检不合格均占用车辆） |
| 派车 | 保养停机车辆不可派任务；每车最多一个执行中任务 |
| 备件占用 | 领用先"占用"（可用 = 库存 − 全车队占用），拆单占用同样不能超过库存 |
| 核销 | "领用核销"时才真正扣减库存；占用不超量、出库再兜底校验 |
| 缺件 | 转"待料"后**释放该工单全部已占数量**，车辆继续停机；备件入库且数量足够才可复工 |
| 完工 | 必须录入完工里程（≥当前里程）、质检结果、旧件回收数量（已领用备件至少回收 1 件） |
| 质检 | 不合格 → 退回待修，不冻结、车辆继续停机，保留不合格记录；合格 → 工单冻结、写入车辆里程 |
| 冻结补录 | 冻结后备件与里程均不可改；补录只生成**带原因的递增版本**（里程订正留痕、备件补录不扣库存） |
| 一致性 | 内置 `auditState` 自检（占用超库存、单车多在修单、停机与执行中并存、版本号不连续等），异常在界面顶部展示 |

## 架构：数据 / 规则 / 界面分离

```
src/
├── data/                 # 数据层：只描述数据，不含任何判断
│   ├── types.ts          #   领域类型与状态常量
│   ├── seed.ts           #   演示种子数据
│   └── storage.ts        #   localStorage 快照存取 / 版本兼容
├── rules/
│   └── fleet.ts          # 规则层：纯函数，全部业务规则集中于此，
│                         #   违规则 throw RuleError；不依赖 Vue/DOM，可独立单测
├── stores/
│   └── fleet.ts          # 编排层：Pinia store，深拷贝草稿上跑规则，
│                         #   成功才整体提交落盘（失败不留半截修改）+ 派生查询
└── ui/                   # 界面层：只做展示与表单交互，不直接改数据
    ├── DispatchPanel.vue #   车辆调度
    ├── RepairPanel.vue   #   报修开单（含紧急回收）+ 工单筛选
    ├── RepairCard.vue    #   单张工单：备件占用/核销、缺件待料、完工质检、补录版本
    ├── PartsPanel.vue    #   备件库存 / 入库 / 待料工单
    ├── Toasts.vue        #   操作反馈
    └── toast.ts
```

规则层典型用法（与界面无关）：

```ts
import { createRepair, occupyPart, turnToWaiting, completeRepair } from "./rules/fleet";
// createRepair 会自动校验"执行中不能报修""紧急必须回收+原因""单车一张在修单"
// occupyPart 按"库存 − 全车队占用"校验；turnToWaiting 会释放该单全部占用
// completeRepair 不合格退回待修，合格冻结并回写里程
```
